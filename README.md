# @kamaldgrt/ui

Shared React UI primitives styled with Tailwind CSS theme tokens:

- **`Modal`**: centered dialog. Backdrop click and Escape close it, and the first field gets focus on open.
- **`Button`**: text button in three looks (`primary` filled CTA, `secondary` white with a border, `danger` solid red) and two sizes (`md`, `sm`).
- **`ConfirmModal`**: message plus Cancel and Confirm, with an optional `danger` style and an optional secondary action.
- **`PromptModal`**: one or more labeled text inputs plus Cancel and OK. It replaces `window.prompt`.
- **`Drawer`**: slide-over panel (right by default, `side="left"` for the left) with an enter and exit transition and an optional header icon.
- **`FloatingCard`**: a drawer that floats. A rounded card inset from the top-right corner instead of a full-height slide-over, with an optional subtitle under the title and a `footer` pinned under the scrolling body. Dismisses like `Drawer`.
- **`SearchableSelect`**: single-select with a search box. Ids can be strings or numbers, options can have icons, and an optional `allLabel` is a pinned "no filter" choice.

All components are client components (`"use client"` is included in the build).

## Requirements

- React 19
- `lucide-react` (peer dependency, used by `Drawer` and `FloatingCard`)
- Tailwind CSS v4 in the consuming app

## Install

```bash
npm i @kamaldgrt/ui
```

## Setup in the consuming app

The components carry Tailwind class names, so the app's Tailwind build has to scan the package. Add this to the app's main stylesheet. The path is relative to that file:

```css
@import "tailwindcss";
@source "../../node_modules/@kamaldgrt/ui/dist";
```

Without the `@source` line, Tailwind never sees the package's classes and the components render unstyled.

### Theme tokens

The components use semantic color tokens, so each app keeps its own look. The app must define these under `@theme` as `--color-*` variables:

| Token | Used for |
|---|---|
| `surface`, `surface-elevated`, `surface-hover` | backgrounds, dialog card, hover state |
| `foreground`, `muted` | text |
| `border`, `border-subtle` | borders |
| `cta`, `cta-foreground`, `cta-hover` | primary button |
| `danger-bg`, `danger-text` | destructive button |
| `warning-bg`, `warning-text` | drawer icon chip |

```css
@theme {
  --color-surface: #ffffff;
  --color-foreground: #111827;
  /* ...and so on for every token above */
}
```

## Usage

```tsx
import { Button, ConfirmModal, Drawer, FloatingCard, Modal, PromptModal, SearchableSelect } from "@kamaldgrt/ui";

<Button variant="secondary" size="sm" onClick={cancel}>Cancel</Button>

<ConfirmModal
  isOpen={open}
  onClose={() => setOpen(false)}
  onConfirm={remove}
  title="Delete item"
  message="This cannot be undone."
  confirmLabel="Delete"
  danger
/>

<Drawer isOpen={open} onClose={() => setOpen(false)} title="New item" icon={Plus}>
  <ItemForm />
</Drawer>

<FloatingCard
  isOpen={open}
  onClose={() => setOpen(false)}
  title="Guardian contacts"
  subtitle="Maya Chen"
  footer={<button onClick={() => setOpen(false)}>Close</button>}
>
  <ContactList />
</FloatingCard>

<PromptModal
  isOpen={open}
  onClose={() => setOpen(false)}
  onSubmit={({ name }) => rename(name)}
  title="Rename"
  fields={[{ name: "name", label: "Name", defaultValue: current }]}
/>

<SearchableSelect
  ariaLabel="Status"
  options={[{ id: "open", label: "Open" }, { id: "done", label: "Done" }]}
  value={status}
  onChange={setStatus}
  allLabel="Any status"
/>
```

Behavior worth knowing:

- A `Drawer` stays mounted for 200 ms after `isOpen` turns false so the slide-out can play. Its children remount on every open, so forms start fresh.
- Pressing Escape inside a `Drawer` or `FloatingCard` that contains an open dialog closes only the dialog.
- `FloatingCard` has the same 200 ms exit, remounts its children on every open, and takes `widthClassName` (replaces the default `sm:w-[540px]`) and `closeButtonClassName` like `Drawer`. It is full width minus a 1 rem gap on narrow screens and never taller than the viewport minus 2 rem; the body scrolls, the header and footer stay.
- `Button` takes `variantClassName` and `sizeClassName`, and `FloatingCard` takes `classNames` (parts: `card`, `header`, `title`, `subtitle`, `closeButton`, `body`, `footer`). Each replaces that part's default classes, so an app can restyle them from its own code without a new release of this package. Parts and props you omit keep the defaults. Positioning and the open/close transition are not overridable.
- `Modal` takes an optional `className` that replaces the default card styling.
- `Drawer` takes `side` (`"right"` default or `"left"`), `widthClassName` (replaces the default `sm:max-w-md`) and `closeButtonClassName` (added to the close button, e.g. `min-h-10 min-w-10` for a larger tap target). Classes you pass are generated by your own app's Tailwind scan.
- There is no focus trap. One dialog at a time is the supported case.

## Development

```bash
npm install
npm test            # vitest (jsdom, testing-library)
npm run typecheck   # tsc --noEmit
npm run build       # tsup -> dist/ (ESM + .d.ts)
```

## Updating

Check the latest version with `npm view @kamaldgrt/ui version`, then bump it in the consuming app:

```bash
npm i @kamaldgrt/ui@latest
```

While the major version is `0`, a caret range such as `^0.2.0` only accepts patch releases (`0.2.x`). A new minor (`0.3.0`) is never picked up automatically, so bump it explicitly. From `1.0.0` on, `^1.x.y` accepts every minor and patch.

After updating, run the app's typecheck, tests and build.

## API changes

Everything is imported from the package root. Treat exported names, props and the list of theme tokens as a public API:

- Additive changes (new optional props, new components, new tokens with a fallback) bump the minor version.
- Breaking changes (removed or renamed props, new required tokens) bump the major version.
- Tag each release (`vX.Y.Z`) to match the published version.
